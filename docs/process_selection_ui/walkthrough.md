# ウォークスルー: プロセス選択ウィンドウのUI更新

## 実装された修正

### 1. アクリル/Micaの互換性

- **問題**: `AllowsTransparency="True"` は、一部のWindowsバージョンで最新のDWMバックドロップ（アクリル/Mica）が正しくレンダリングされるのを妨げます。
- **修正**:
  - `AllowsTransparency="False"` に設定しました。
  - レガシーな透明モードなしでフレームと透明度を適切に処理するために `<WindowChrome ... GlassFrameThickness="-1" ... />` を追加しました。

### 2. スクロールバーの可視性

- **問題**: `ScrollBar` の暗黙的なスタイルが `ListBox` 内部の `ScrollViewer` に適用されていませんでした。
- **修正**:
  - `ThinScrollBar` を使用する明示的な `ThinScrollViewer` スタイルを作成しました。
  - `ListBox.Resources` を介してこの `ThinScrollViewer` スタイルを `ListBox` に適用しました。

## 修正ラウンド2

### 1. 堅牢なアクリルブラー

- **問題**: 標準の Win11 `DwmSetWindowAttribute` によるアクリル設定では、ブラー（ぼかし）のない透明状態になっていました（テーマやドライバ設定、APIの微細な挙動による可能性）。
- **修正**: `ACCENT_ENABLE_BLURBEHIND` (3) を使用する、ドキュメント化されていないものの信頼性の高い `SetWindowCompositionAttribute` に戻しました。これは Windows 10 と 11 の両方で標準的な「すりガラス」のブラーを提供します。

### 2. スクロールバーの適用

- **問題**: 明示的なスタイル設定が `ListBox` 内部の `ScrollViewer` に到達していませんでした。
- **修正**:
  - `ProcessSelectionWindow.Resources` 内の `ScrollBar` スタイルの `x:Key` を削除しました。
  - これによりスタイルが**暗黙的**になり、ウィンドウ内の*すべて*のスクロールバーに自動的に適用され、`ListBox` が確実に薄い(2px)スタイルを使用するようになります。

## 修正ラウンド3 (回帰修正と持続的な問題)

### 1. メインウィンドウのアクリル効果の復元

- **問題**: 前回の `WindowHelper` の変更により、Windows 11で `DwmSetWindowAttribute` (Mica/Acrylic) に依存していたメインウィンドウの効果が失われました。
- **修正**: `WindowHelper` を元に戻し、Windows 11では `DwmSetWindowAttribute` を優先するようにしました。プロセスウィンドウに対してもこれが機能するように設定を調整しました。

### 2. プロセス選択ウィンドウの問題

- **問題**: プロセス選択ウィンドウが透明（背景なし）になり、ブラーが効いていない。またスクロールバーがまだ太い。
- **修正**:
  - プロセス選択ウィンドウの `Background` を `Transparent` から明示的な半透明色 (`{StaticResource WindowBackground}`) に変更しました（`AllowsTransparency=False` 環境下でのアクリル表示に必要）。
  - スクロールバーのスタイル定義を `ListBox.Resources` 内に直接移動し、スコープを限定して確実に適用されるようにしました。

## 修正ラウンド4 (最終フォールバック)

### 1. 非透過ダーク背景への変更

- **問題**: ユーザー環境においてプロセスウィンドウのアクリル効果が安定せず、また透明になりすぎて視認性が悪いというフィードバックがありました。
- **修正**:
  - アクリル効果の適用 (`ApplySystemBackdrop`) を無効化しました。
  - ウィンドウの背景色を不透明なダークグレー (`#1F1F1F`) に設定しました。
  - これにより、視認性の高いダークモードUIとなります。

### 2. ファイル参照時のクラッシュ修正

- **問題**: 「参照」ボタンを押してファイルダイアログを開こうとすると、`ExplorerBlurMica.dll` がフックしている最新のファイルダイアログ (Common Item Dialog) と競合し、例外が発生してクラッシュします。WPFのダイアログでも解決しませんでした。
- **修正**:
  - 再び `System.Windows.Forms.OpenFileDialog` を使用しますが、**`AutoUpgradeEnabled = false`** を設定しました。
  - これにより、Vista以降のスタイルではなく、古い（WinXPスタイルの）ファイル選択ダイアログが強制的に使用されます。
  - `ExplorerBlurMica.dll` は古いAPI (`GetOpenFileName`) をフックしない可能性が高いため、これでクラッシュを回避できる見込みです。見た目は古くなりますが、動作の安定性を優先しました。

## 検証手順

1. **アプリを実行する**。
2. **プロセス選択画面を開く**。
3. **「ファイル参照...」などをクリック**:
   - [ ] **クラッシュしないこと**: 古いスタイルのファイル選択ダイアログが開き、ファイルを選択できること。
