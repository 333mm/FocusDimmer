# 修正内容の確認 (Walkthrough)

## 修正された問題

1. **PC再起動時に減光されない**
    - **原因**: アプリの初期化処理が `Loaded` イベント内で行われていたため、ウィンドウが表示されないトレイ起動（AutoStart）時には実行されていませんでした。
    - **修正**: 初期化処理を `Loaded` イベントから切り離し、コンストラクタから呼び出される `InitializeAppAsync` メソッドに移動しました。
    - **結果**: ウィンドウの表示状態に関わらず、起動直後から確実に減光が開始されます。

2. **設定が保存されない（消失する）**
    - **原因**: 初期化処理がスキップされると、設定ファイルの内容がメモリ上に展開されず、その後の保存処理で空の設定（デフォルト値）が上書き保存されていました。
    - **修正**: 上記の通り初期化処理を確実に実行するようにしたため、設定ファイルが正しく読み込まれてから保存されるようになります。

## 検証方法（シミュレーション）

1. **AutoStart 時の挙動**
    - `App.xaml.cs` は `IsAutoStart` が true の場合 `Show()` を呼び出しませんが、`MainWindow` のインスタンスは作成されます。
    - `MainWindow` のコンストラクタが実行され、その最後で `InitializeAppAsync()` が呼ばれます。
    - `InitializeAppAsync()` 内で `InitializeMonitors()` が実行され、各モニターの `DimmerOverlay` ウィンドウが作成・表示されます。
    - これにより、メインウィンドウを開かなくても画面が暗くなります。

2. **設定の整合性**
    - コンストラクタ呼び出し完了時には、`InitializeAppAsync` による設定の読み込み（`InitializeMonitors` 内でのプロファイル適用など）が完了しています（非同期部分はawaitされますが、重要なロジックは同期的に走るか待機されます）。
    - ユーザーがトレイアイコンから設定を開いたときには、既に正しい設定がロードされた状態になっています。
