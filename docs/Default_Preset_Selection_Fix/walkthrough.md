# デバッグ用Pro切り替えスイッチの実装と修正

デバッグ構成でのみコードが存在し、リリース構成には一切の影響を与えない形でPro版切り替えスイッチを実装しました。また、そのスイッチ操作時に発生していたプリセット選択の不具合を修正しました。

## 実施内容

### 1. コードの条件付きコンパイル

`MainWindow.xaml.cs` において、`IsProDebugToggle` および `DebugModeVisibility` プロパティの **定義そのもの** を `#if DEBUG` ブロックで囲みました。これにより、Releaseビルドではこれらのプロパティはコンパイル後バイナリに存在しなくなります。

### 2. XAMLバインディングの安全化

プロパティが存在しないReleaseビルドで実行時エラー（バインディング失敗）が発生してもUIが崩れないよう、XAML側で `FallbackValue` を設定しました。
`Visibility="{Binding DebugModeVisibility, FallbackValue=Collapsed}"`

### 3. プリセット選択ロジックの修正

Proスイッチ切り替え時（`InitializeMonitors` 実行時）に、意図せず「リストの最初のプリセット」が選択されてしまう問題を修正しました。

- **修正前:** `SelectedGlobalPresetId = _appSettings.SelectedPresetId ?? "";` (単純な復元のみ)
- **修正後:** 以下の優先順位で選択を決定するロジックを追加。
    1. **直前の選択状態**: リスト再構築前に保持していたIDが有効なら維持。
    2. **既定のプリセット**: 上記が無効なら、ユーザーが設定した「既定(Default)」を使用。
    3. **リストの先頭**: 上記もなければ、リストの最初の項目を使用。

この変更により、Proスイッチを切り替えても、ユーザーが「既定」に設定したプリセットが正しく維持されるようになりました。

## 検証結果

- [x] **Debugビルド:** プロパティが存在し、スイッチが表示・機能することを確認。
- [x] **プリセット選択:** スイッチ切り替え直後、勝手に最初のプリセットに戻らず、正しく「既定のプリセット」または「直前のプリセット」が維持されることを確認。
- [x] **Releaseビルド:** 実装が含まれないことを設計上確認済み。
- [x] `dotnet build` 正常終了。
