# ホワイトリスト減光バグの修正結果

## 概要

「非アクティブモニターを暗くする」や「アイドル時に暗くする」機能により全画面が暗転する際、「常に明るくする」リスト（ホワイトリスト）に登録されているアプリケーションまで暗くなってしまう不具合を修正しました。

## 実施した変更

### `DimmerOverlay.cs` の修正

1. **強制暗転 (forceNoHoles) 時の挙動変更**:
    - 従来は `forceNoHoles` フラグが立っていると、あらゆる「穴あけ処理」をスキップして即座にリターンしていました。
    - 修正後はリターンせず、条件付きで穴あけ処理を続行するように変更しました。

2. **穴あけ条件の厳格化**:
    - 強制暗転モード時は、以下のように挙動を制御します。
        - **アクティブウィンドウ**: 穴を開けない（スキップ）
        - **タスクバー**: 穴を開けない（スキップ）
        - **ホワイトリスト**: **穴を開ける**（従来はスキップされていた）

    ```csharp
    // forceNoHoles モードでも specialWindows (ホワイトリスト) の処理は続行
    if (forceNoHoles) 
    {
        // 早期リターンを削除
    }

    // ...

    // 通常のウィンドウやタスクバーは forceNoHoles ではスキップ
    if (!forceNoHoles && targetHwnd != IntPtr.Zero && ...) { ... }
    if (!forceNoHoles && LinkedProfile.ExcludeTaskbar) { ... }

    // ホワイトリスト対象はそのまま穴あけ処理を実行
    foreach (var rect in specialWindows) { ... }
    ```

3. **対象ウィンドウの抽出ロジック**:
    - ウィンドウ列挙時も、`forceNoHoles` が有効な場合は「最前面ウィンドウを除外」オプションを無視し、純粋に「常に明るくする」リスト（およびメニュー）だけを抽出するようにロジックを調整しました。

## 結果

これにより、「全画面を暗くする」設定が有効な場合でも、ユーザーが意図してホワイトリストに追加したチャットアプリや動画プレイヤーなどは、常に明るい状態で表示されるようになります。
